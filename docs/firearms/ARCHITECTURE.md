# Firearms: architecture

For whoever implements the firearms. Read `docs/firearms/RESEARCH.md` first (its "Principles we keep" are the rules this design follows), then `docs/references/README.md` and `docs/references/video17.md` (no freeze, no snap, overlap, arcs, inertialized transitions; never more than ~20° per frame at 60 fps except deliberate snaps).

Status: design only. Nothing here is built yet. Phase 1 (models + solved holds) starts from §5 and §7.4.

The bar is the Pyromaniac's flamethrower: a procedural Blender model with named parts and marker points (`tools/pyro/flamethrower.py`), a primitives rebuild for the game with an optional FBX (`tools/pyro/flamethrower_parts.py` → `src/client/Combat/FlamethrowerShape.luau`, `src/client/Combat/Flamethrower.luau`), holds SOLVED for rigid R6 arms (`solve_hold`, `tools/anim/pyro_clips.py` `solve_right` / `solve_left`), renders looked at by eye, and checks that fail loudly (`pyro_clips.py --check`). Every gun follows the same pipeline.

---

## 1. Goals and non-goals

Goals:
- Five weapons, each complete: a compact polymer 9 mm pistol, a semi-auto 12-gauge, a 7.62×39 AK-type rifle, a .338 bolt-action sniper with a bipod, a 5.56 belt-fed LMG with a 200-round pouch.
- Gun HANDLING first: weight, posture, arms that stay on the gun, smooth stance changes, real manipulation (mag, slide, charging handle, bolt, shells, feed cover), moving with the weapon, animations that match the model's moving parts.
- Casings that eject and stay on the floor; magazines (and the LMG pouch) that drop and stay.
- Server-authoritative shots that feel instant to the shooter.
- Nothing in the existing melee, kits, finishers, gore or locomotion changes behaviour when nobody holds a gun.

Non-goals (for now): a first-person viewmodel (the world model is the only model), attachments / customisation, malfunctions (a later idea), vehicles, prone (see open questions), mobile controls (the game is PC-only, `docs/DESIGN.md` §2).

## 4. Weapon data

### 4.1 The definition

```luau
export type FireMode = "Semi" | "Auto" | "Bolt"
export type Class = "Pistol" | "Shotgun" | "Rifle" | "Sniper" | "Lmg"
export type Zones = { Head: number, Torso: number, Arms: number, Legs: number }

export type SpreadDef = { -- degrees, half-angle of the cone
	hip: number, ready: number, ads: number, -- standing still
	moving: number, -- added at full walk speed (scaled by speed)
	crouch: number, -- multiplier while crouched
	bipod: number?, -- multiplier deployed
	perShot: number, max: number, -- bloom added per shot, cap of the bloom
	recover: number, -- bloom lost per second
	pellets: number?, pelletCone: number?, -- shotgun: pellets per shell, their cone
}

export type RecoilDef = {
	-- gameplay (moves the aim, so the bullets): degrees per shot
	climb: number, climbFirst: number, -- first shot of a burst multiplier
	yaw: number, yawBias: number, -- random ± and constant drift (+ = right)
	recover: number, recoverTime: number, -- fraction given back after the burst, over seconds
	-- the body (visual), springs
	kick: number, push: number, -- gun pitch (deg) and push back (studs)
	roll: number, -- alternates sign each shot
	torso: number, -- Root pitch back (deg)
	frequency: number, zeta: number, -- Hz, damping ratio
	shake: number, -- cosmetic camera shake (deg)
	bipod: number?, crouch: number?, -- multipliers
}

export type HandlingDef = {
	massKg: number, -- loaded
	adsTime: number, sprintToFire: number, raiseTime: number, -- low ready → ready
	drawTime: number, holsterTime: number,
	lookLagHz: number, lookLagMax: number, -- degrees
	walkSpeed: number, adsWalkSpeed: number, -- multipliers of the kit's speed
	canSprint: boolean,
	tuckLength: number, -- studs: shoulder pocket → muzzle (wall check)
}

export type FirearmDef = {
	id: string, name: string, class: Class, caliber: string,
	modes: { FireMode }, rpm: number, -- cyclic; semi is capped at it
	feed: "Magazine" | "Tube" | "Belt",
	capacity: number, closedBolt: boolean, -- closed bolt: +1 in the chamber
	startAmmo: number, -- rounds carried besides the loaded mag (pickup)
	damage: number, -- per bullet / pellet, Torso, at the muzzle
	zones: Zones,
	falloff: { full: number, zero: number, min: number }, -- studs, studs, multiplier
	range: number, -- studs, the ray length
	pierce: number, -- bodies a bullet can pass through (0 = stops on the first)
	spread: SpreadDef, recoil: RecoilDef, handling: HandlingDef,
	timelines: string, -- key in Shared/Firearms/Timelines (reload, cycle, draw clips)
	eject: EjectDef, -- §10
	scope: { fov: number, overlay: string }?, -- magnified optics
	displayScale: number, -- 1 = real size (see open questions)
}
```

## 5. Model contract

Every gun model must satisfy this. `tools/guns/check_model.py` enforces it; the game code (`GunModel`, `Handling`, `Casings`, `Magazines`, `MuzzleFx`, the hold solver and the clip tool) relies only on it.

### 5.1 Units, axes, origin, rest state

- **Units:** Blender scene in metres, unit scale 1.0, object scales applied (1, 1, 1). Real dimensions within ±3 % of the target in §5.6. In game, **1 stud = 0.28 m** (as the flamethrower).
- **Axes (model space):** right-handed, **+X = muzzle forward (the bore direction), +Y = the gun's left, +Z = up**. Game gun space is studs with −Z = muzzle (LookVector), +X = right, +Y = up: `roblox = (−y, z, −x) / 0.28` (exactly `flamethrower_parts.py`'s conversion).
- **Origin:** (0, 0, 0) on the bore axis at the breech face (where the case head sits when chambered). The bore is the X axis (y = 0, z = 0).
- **Angles in hinge specs:** degrees, right-hand rule about the listed axis in model space. With +Y as the axis, a positive angle moves a point BELOW the pivot to the rear and a point IN FRONT of the pivot downward.
- **Rest state (as exported):** mag (or pouch and belt) seated and full, slide / bolt / carrier / charging handle forward and locked, feed cover closed, trigger forward, selector on SEMI where there is one, bipod folded, stock and cheek piece at their default length, no round visible in an ejection port.
- **Names:** PascalCase object names exactly as listed (no `.001` suffixes). Materials named by paint key (`Polymer`, `SteelBlued`, `SteelPhosphate`, `SteelLacquer`, `Aluminium`, `Wood`, `Rubber`, `Fabric`, `FabricTan`, `FabricCamo`, `Brass`, `Lens`, `Glow`, `Reticle`, `Stamp`...). Children that move with a moving part are parented to it in Blender and listed in the JSON `groups`.
- **Markings:** no brand logos, trademark names or copied engravings; only generic stamps (calibre, a serial-like code such as `RB-04127`, selector letters).
- **Budgets:** FBX ≤ 25 MeshParts per gun, ≤ 8 000 triangles (LMG ≤ 12 000, pistol ≤ 4 000); casing ≤ 150 triangles, round ≤ 200, mag ≤ 1 200; primitives rebuild ≤ 60 parts (pistol) / ≤ 150 parts (long guns).
- **Nothing that works as a schematic:** only parts that are seen or move on screen are modelled.

## 6. Dressing the character (GunModel)

- **Who:** any model with the `Firearm` attribute (players, dummies, corpses' pickups), watched like `Flamethrower.watch`. All parts show only (no collision, no query, no touch, massless), welded to an invisible gun root.
- **One joint for the gun:** a Motor6D `GunJoint`, Part0 = Torso, Part1 = gun root. `Handling` writes its `Transform` every frame in PreSimulation (with the body joints). Whatever "owns" the gun (§7.2), its pose is converted to Torso space and written here. So the gun follows clips, springs and the torso bob, and never needs a weld remount (no tween pop like a re-parent).
- **Moving parts:** each hinge is a Motor6D inside the gun (C0 at the pivot from `PIVOTS`), its Transform written from the clip tracks (§8) and the per-shot cycle: at 60 fps a slide or carrier cycles faster than a frame, so the shot frame shows it back and the next frame forward (pistol, rifle, shotgun handle); on the last round the slide / bolt stays back (`GunBoltOpen`). LMG: per shot the visible belt segments twitch one link pitch and snap back; segments hide as the count drops below 12.
- **Mag:** the `Magazine` part is its own joint; a clip moves it between "gun" (on `MagWell`), "left hand", "right hand" and "hidden"; drops are §11.
- **Carried, not drawn:** pistol in a generic polymer holster on the right hip (Torso space ≈ (0.85, −0.85, 0.05) studs, muzzle down); long guns slung diagonally across the back on `BackMount` with a visible strap (tan for the LMG), like the flamethrower's sling. The holster / sling are parts of the gun's dressing.
- **Draw / holster:** clips with an owner switch at the frame the hand meets the grip (§7.2).
- **Stunned / knocked down / KO / dead / ragdolled:** Handling stops writing; the gun is dropped by the server as a pickup at the hand (see open questions for long guns staying slung). Corpse copies never carry a gun.
- **Points:** Attachments named after the markers (`Muzzle`, `EjectionPort`, `CasingSpawn`, `SightEye`...) for effects, sounds and the camera.
- **Look:** paints like `FlamethrowerShape.PAINTS` (matte polymer, phosphate steel, worn bluing, oiled wood, rubber, tan cordura); wear on edges (bare steel), grime in recesses.

## 7. Handling animation on R6

### 7.1 The layers (every armed character, every client, PreSimulation)

`CharacterAnimationController.compose` already does: locomotion → movement channel → sprint lean → stance channel → lean / bank → action channel → flinch → body turn lag → pins → inertialization. When a character is armed, the armed hook (`Handling.compose`) runs after the stance channel and lean, and owns the upper body:

1. **Locomotion (unchanged):** ALS legs, Root bob, lean into acceleration, body turn spring (`Locomotion`). While aiming, `Locomotion.update(..., busy = true)` so the body turn spring is fast (as during a move), and the gun pose is stabilised in HRP space anyway.
2. **Stance pose:** sample `GunHolds[weapon][stance]` at the current aim pitch and tuck (Hermite across the rows), then blend stances with the timed transitions of §7.6. Output: the gun's pose (6 DOF) and twist references for both shoulders, a Root additive (blade yaw, pitch share, crouch nothing extra), Neck.
3. **Action clip:** reload / cycle / draw / holster / bipod (`GunClips`), weighted by its own fade; it can override the gun pose, the owner, the hand targets and IK weights, and the moving parts.
4. **Aim offset:** the remaining pitch / yaw to the aim point, as a rotation of the gun pose about the shoulder pocket (long guns) or the shoulders' midpoint (pistol), clamped to the solved row range.
5. **Procedural additive (springs):** look lag, move sway, footstep bob, breathing + muscle noise, landing bump, hit flinch, then recoil impulses. Gun pose offsets, Root rock, Neck counter (one frame late).
6. **Arm solve:** each arm aimed so its hand point lands on its target (`GripR` / `GripL` on the final gun pose, or a clip's off-gun target), twist from the reference, blended by the clip's IK weight.
7. **Neck look-at** and head stabilisation (the eye on the sight line in ADS).
8. **Rate limit:** each written joint and the gun pose step ≤ 20° / frame at 60 fps (1200°/s, scaled by dt) unless the frame is a flagged snap (shot impulse, mag seat, bolt / slide / handle slam, cover slap).

The action channel (punches, hit reactions) still runs after it: hit reactions blend on top at reduced weight (0.35) so a shot person still flinches with the gun in hand.

### 7.2 One owner for the gun

| Owner | When | Gun pose source |
|---|---|---|
| `Torso` (default) | holding the gun in two hands, any stance | stance pose + clip + aim + springs, in HRP space blended to Torso space by the stance's `stabilise` weight (1 ADS, 0.85 ready, 0.3 high / low ready, 0 sprint) |
| `RightArm` | draw, holster, one-hand carry (climb, vault), the pistol's sprint pump | the right arm's frame × the clip's hand-relative offset |
| `LeftArm` | rare (the LMG carry handle) | the left arm's frame × offset |
| `World` | bipod deployed | fixed in the world; the body moves behind it within ±0.4 stud and ±30° yaw |

An owner switch keeps the gun where it was and melts the difference away with the repo's inertialization (half-life 0.06 s). Arms are always derived from the gun (or from a clip target), never the other way round, except under the `RightArm` owner (then the gun derives from the arm).

### 7.3 Holds per class

R6 facts (`pyro_clips.py` rig): torso 2×2×1 studs; shoulder pivots at Torso (±1, 0.5, 0), 2 studs apart; arm hand point 1.505 studs from its pivot; head centre (0, 1.5, 0); eye ≈ (0, 1.6, −0.45). Arms cannot bend, so "compressed" holds (close ready, sul, a pistol tight at the chest) are impossible; we substitute low / high ready.

- **Pistol, two-hand isosceles (default):** both arms extended forward and converging (each yaws inward ~15–20°), hands meeting about 1.5 studs ahead of the chest, gun at eye height minus the sight height; Root blade 8–12° right. The left hand point on `GripL` (left grip panel), the eye ON the sight line (`SightEye` +X ray, distance ≤ 0.03 stud) rather than at a fixed eye relief. Weaver variant: blade 30°, the left arm shortens its reach by the blade; used for one-hand-supported moves.
- **Long guns, shouldered:** right hand on `GripR`, stock butt (`Shoulder`) in the shoulder pocket (Torso ≈ (0.75, 0.55, −0.55), allowed inside the top front of the right arm block, which IS the R6 shoulder pocket), left hand on `GripL` (handguard / forend). With rigid arms on shoulders 2 studs apart, the grips 1.0–1.6 studs apart along the gun need a torso blade of ~40–60° (the flamethrower needed ~40°): the solver finds it. Cheek weld: Neck roll 8–12° toward the stock, pitch down 4–6°, so the eye sits on the sight line (scopes: at `SightEye` ± 0.03 m).
- **Sniper / LMG on a bipod:** owner `World`; the body solved behind the planted gun.
- **LMG low carry:** the left hand on the `CarryHandle` or under the handguard, the gun across the belly.

### 7.4 The hold solver (`tools/guns/solve_holds.py`)

Offline, per weapon × stance × aim-pitch row × tuck column, least squares in the style of `solve_hold` / `solve_right` / `solve_left`:
- Unknowns: Root yaw / pitch / roll and drop, the gun's 6-DOF pose in Torso space, both shoulders (3 each), Neck (3).
- Constraints (weighted costs): the bore along the stance's aim direction (pitch row); the right hand point on `GripR` and the right arm within 25° of `GripR` +Z; the left hand point on `GripL` and within 35°; shouldered stances: `Shoulder` in the pocket; ADS: the eye on the sight line (scopes: at `SightEye`); no gun point inside the torso or head boxes (except the butt in the pocket); arms not through the torso; preferences (blade near the class's value, low root roll, head upright outside ADS).
- Rows: pitch −60, −30, 0, +30, +60 (pistol); −50, −25, 0, +25, +50 (long guns, limited by the stock). Tuck columns 0, 0.5, 1 (the gun pulled back 0, 0.3, 0.6 stud along the bore for the wall check, §7.8).
- Stances solved: `LowReady`, `Ready`, `Aim`, `HighReady`, `SprintCarry`, `ObstructedHigh`, `ObstructedLow`, `Bipod` (sniper, LMG), plus the holster / back carry reference.
- Limits (exit 1 above): right residual ≤ 0.05 stud, left ≤ 0.10 stud, butt ≤ 0.15 stud from the pocket, eye-to-sight-line ≤ 0.03 stud in ADS, no penetration. Residual over 0.1 stud shows as a floating hand.
- Output: `GunHolds.luau` + renders of every hold on the R6 dummy (front, side, top, eye view), looked at by eye before anything else is built. The model's `GripL` / `Shoulder` / scale may be changed to make the solve converge (the contract's markers are the design lever, as `solve_hold` found the flamethrower's foregrip).

At runtime the arms are re-solved analytically after the springs (look-at of the arm's pivot-to-hand vector onto pivot-to-target, twist from the solved reference). The springs move the gun a few hundredths of a stud, so the residual stays within the limits; the solved poses carry the large changes.

### 7.5 Stances (state machine, per character)

```
Holstered ─draw→ Drawing ─→ Ready ⇄ Aim
                         Ready ─4 s no fire/aim (pistol 6 s)→ LowReady ─LMB / RMB→ Ready (raise)
                         any ─Shift→ Sprint ─release→ (sprint-out) Ready
                         any ─wall > 45 %→ ObstructedHigh/Low ─< 35 % + 0.15 s→ previous
                         any ─R→ Action(Reload...) ─end→ previous (Aim if RMB held)
                         Ready/Aim ─T near a surface→ Bipod ─T / move→ Ready
                         HighReady: automatic on stairs and steep slopes, or a key (optional)
                         any ─X→ Holstering → Holstered
```
Crouch (`C`, existing) is not a separate stance: the same holds with the crouch's Root drop; crouched spread × 0.8, recoil × 0.85. Slide (sprint + C): sprint carry. Climb / vault: owner `RightArm`, carry pose (long guns on the right forearm), arms follow the climb clip.

- Stance changes are **timed Hermite blends** that start from the current pose AND its speed (the repo's inertialization idea) and end at rest on the target at exactly the listed time, so "time to aim" is honest gameplay. Per-joint timing like a UE blend profile: the head arrives first (×0.7), arms at ×1, Root last (×1.2).
- Firing is allowed from `Ready` and `Aim`; from `LowReady` a fire press raises first (raise time), then fires. Sprint → fire waits for sprint-out.
- The outgoing pose keeps moving during a blend (no frozen last frame); anticipation of a clip is never eaten by a cross-fade (the clip's first keys hold until its weight is above 0.7).

### 7.7 The procedural layer

Underdamped springs (`Spring.stepDamped`), skipped when dt > 0.1 s; inputs normalised as sreitich does.
- **Look lag:** input = view angular velocity (yaw ÷ 720°/s, pitch ÷ 360°/s, zeroed on the first frame) → gun yaw / pitch offset opposite to the turn, max 6°, at the def's `lookLagHz`, ζ 0.6; Root takes 30 %, the Neck leads (head first, gun trails).
- **Move sway:** local velocity ÷ walk speed → pistol roll 2–4°; long guns 0.04–0.07 stud back and a 1–2° cant into strafes.
- **Footstep bob:** an impulse on each `Locomotion` step (they are reported per foot) of 0.5–1° pitch and 0.02 stud down (sniper / LMG ×2), scaled by speed; limping (`Limping` attribute) doubles it on the bad leg.
- **Breathing:** rest 0.22 Hz, 0.3° vertical; after sprinting 0.55 Hz, 2°, decaying to rest over 8 s (driven by the `Stamina` attribute); plus 3 octaves of noise at ≤ 0.3°. Low stamina × 1.6 sway; under 25 HP a tremor (+0.4°).
- **Hold breath (sniper scoped):** Shift while scoped: sway × 0.15 for up to 4 s (stamina 6 / s), then 1.5 s of × 2.
- **Landing bump:** pitch dip 3–8° scaled by the landing speed, recovery 0.25 s.
- **Hit flinch:** a CombatEvent hit on us kicks the gun spring (2–5°, toward the hit side).
- **Recoil (each shot, §4.2):** an impulse into the gun pitch spring (`kick`, on the shot frame: a flagged snap), the push spring (`push`, pivot at the shoulder pocket for long guns, the wrists for the pistol), the alternating roll, the Root pitch back (`torso`), the Neck one frame later. Bipod × 0.3, crouch × 0.85. Applied before the arm solve so the support hand rides with the gun.

### 7.8 Wall collision (tuck)

Each frame for the local player (20 Hz for others): a raycast (radius 0.15 stud via a sphere cast) from the shoulder pocket along the bore for `tuckLength` + 0.5 stud, against the map only. Penetration p: 0–40 % slides the gun back (tuck column 0 → 1, i.e. up to 0.6 stud) through a spring; above 45 % (back under 35 %) it switches to ObstructedHigh (aim pitch > −10°) or ObstructedLow; fire is blocked while obstructed and for 0.15 s after.

### 7.9 Other players' guns

Others run the same pipeline from replicated state: `Firearm`, `GunDrawn`, `GunAction` (clip and its server start time), `GunMagIn` / `GunBoltOpen` / LMG flags, the 15 Hz aim stream (pitch + stance bits: aim, low / high ready, sprint, bipod, crouch), and `ShotFired` (recoil impulse, flash, casing). The aim stream is interpolated with a 0.1 s buffer then smoothed by a spring; look lag uses the stream's yaw rate. Obstruction is computed locally. LOD: within 60 studs full rate; 60–150 studs the procedural layer at 30 Hz and no wall check; beyond 150 studs stance pose + clips only; beyond the controller's `MAX_DISTANCE` nothing (as now); skip when `Animator.EvaluationThrottled`.

## 8. Clips and reload state machines

### 8.1 Clip format (`GunClips.luau`, generated)

```luau
export type GunClip = {
	length: number, looped: boolean,
	body: R6Pose.Clip, -- Root (additive), Neck, both shoulders (twist references; baked solve)
	gun: R6Pose.Clip, -- one joint "Gun": the gun's pose in Torso space (rot degrees, pos studs)
	parts: R6Pose.Clip, -- joints named after the moving parts: "Slide", "Bolt", "FeedCover", "Magazine"...
	owner: { { time: number, owner: "Torso" | "RightArm" | "LeftArm" | "World" } },
	ikLeft: { { time: number, weight: number } }, ikRight: { { time: number, weight: number } },
	targets: { { time: number, side: "L" | "R", target: string } }, -- "Gun:MagGrab", "Body:MagPouch"...
	mag: { { time: number, at: "Gun" | "HandL" | "HandR" | "Hidden" } },
	events: { { time: number, name: string, snap: boolean? } },
	commitAt: number?, cancelUntil: number?,
}
```
`R6Pose.sample` already samples any joint names with the Hermite spline, so `gun` and `parts` reuse it unchanged. Body markers (pouches on the vest / belt: `Body:MagPouch` front-left of the belt, `Body:ChestPouch`, `Body:ShellCarrier` on the left hip, `Body:BeltPouch` on the left back) live in `GunHolds.luau`.

Events (names fixed): `mag_release`, `mag_drop` (spawn the physics mag), `mag_grab`, `mag_insert` (snap; ammo commit), `slide_back`, `slide_release` (snap), `bolt_lift`, `bolt_back`, `case_eject`, `bolt_forward` (snap), `bolt_lock` (snap), `charge_back`, `charge_release` (snap), `shell_grab`, `shell_insert` (snap; +1), `port_load`, `bolt_release_press`, `cover_open`, `cover_close` (snap), `belt_clear`, `pouch_release`, `pouch_drop`, `pouch_attach` (snap), `belt_lay` (commit), `bipod_deploy`, `bipod_fold`, `draw_grip` (owner switch), `holster_seat`, plus sound cue names. `round_count_commit` is the clip's `commitAt`.

### 8.2 Beats per weapon (seconds; the clip tool may move them, `Timelines.luau` follows)

**Pistol tactical (1.6 s):** 0–0.18 anticipation (gun pulls in 0.4 stud = 0.12 m, cants 20° toward the left hand, head down to the well) · 0.18 `mag_release` · 0.22 `mag_drop` (falls free, slight forward spin) · 0.20 left IK 1 → 0 (0.12 s), left hand to `Body:MagPouch` · 0.55 `mag_grab` · 0.55–0.95 to the well (gun meets the mag) · 0.98 `mag_insert` (commit; bump 3°) · 1.05–1.18 left IK 0 → 1 · press out, spring follow-through to 1.6. Cancel until 0.95.
**Pistol empty (2.0 s):** as tactical to 0.98 · left hand overhand to `SlideGrip` 1.05–1.25 · 1.32 `slide_back` (0.028 m in 0.07 s, counter-motion of the gun) · 1.40 `slide_release` (slam, snap, chambered) · regrip 1.55 · ready 2.0. (Variant: thumb on `SlideStop` at 1.15, −0.3 s.)

**Rifle tactical (2.6 s):** 0–0.25 anticipation (rolls 20° toward the support side, pulls in, muzzle up 10°) · left hand to `Body:ChestPouch`, `mag_grab` 0.75 · 0.80–1.10 the new mag to the old · 1.12 `mag_release` (the new mag's spine on the paddle) · 1.15 `mag_drop` (rocked forward-out about `MagRockPivot`, 4 rad/s forward tumble) · 1.20–1.55 front lug hooked, rocked back · 1.62 `mag_insert` (commit, snap) · left hand to the handguard 1.70–1.85 · settle to 2.6. Cancel until 1.55.
**Rifle empty (3.2 s):** as tactical to 1.62 · right IK 1 → 0 at 1.70, right hand to `ChargeHandle` 1.75–1.98 · 2.10 `charge_back` (0.12 m in 0.08 s) · 2.18 `charge_release` (slam, chambered) · right hand back to `GripR` 2.25–2.50 · settle to 3.2.

**Shotgun (tube):** start 0.40 (roll 75° belly-out, left hand to `Body:ShellCarrier`) · each shell 0.50 (`shell_grab` 0.10, push into `ShellPort`, `shell_insert` 0.38 commit +1, release 0.45) · finish 0.35 (roll back, remount). Cancel after any `shell_insert` (or during the start). Empty: the bolt is locked open (`GunBoltOpen`) → port load 0.9 s first (roll port-up 30°, a shell into `PortLoad` at 0.55: chambered; `bolt_release_press` 0.70, bolt slams) → then the tube loop.

**Sniper bolt cycle (1.0 s, hip and scoped variants):** right hand to `BoltKnob` 0–0.15 · `bolt_lift` 0.15–0.27 (−60°) · `bolt_back` 0.27–0.45 (0.115 m; `case_eject` at 0.43 with a speed from the bolt's speed) · `bolt_forward` 0.45–0.63 (feeds: commit) · `bolt_lock` 0.63–0.73 (snap) · back to `GripR` 0.73–0.85 · settle 1.0. Scoped: the head stays on the stock, the gun rolls 3–5° and dips on the pull. Reload 3.3 s (`mag_release` 0.55, `mag_drop` 0.60, `mag_grab` 1.30, `mag_insert` 2.20 commit); empty 3.9 s (+ bolt back / forward / lock at 2.6 / 2.9 / 3.0).

**LMG belt (7.0 s):** anticipation, cant right 15°, dip · `charge_back` + return 0.6–0.9 (only if the bolt is forward) · left hand to `FeedCoverLatch`, `cover_open` 1.3 · `belt_clear` 1.7 (left segments drop as a short belt piece) · `pouch_release` 2.0, `pouch_drop` 2.2 (cloth thud) · left hand to `Body:BeltPouch`, grab 3.4 · `pouch_attach` 4.2 (snap) · belt end pulled up 4.3–5.2 · `belt_lay` 5.3 (commit 200) · `cover_close` 5.5 (slap, snap; the right hand stays on the grip, the left in front of the optic) · regrip 5.8–6.2 · settle 7.0. Cancel until 5.2, and a cancelled reload leaves the gun in the state it reached (cover open, no pouch): the next reload resumes from there.

**State kept per gun (server and client):** `mag` (rounds in the mag, nil = no mag in), `chambered`, `boltOpen`, LMG `coverOpen`, `pouchOn`, `beltLaid`. A cancel never rolls back a physical step that happened (a dropped mag stays dropped): the next reload picks the shortest clip from the state (pistol / rifle with no mag in: insert only; slide / bolt open: release only).

**Tactical drops the mag:** the old mag falls with its rounds (lost; see open questions for a retention reload on a long press).

### 8.3 Draw / holster / others
Pistol draw (0.55 s): grip (owner `RightArm`, `draw_grip` 0.12) → clear the holster → rotate up, the support hand meets it (owner → `Torso` at 0.35) → press out. Long guns: right hand to the grip over the shoulder, swing the gun round on the sling, left hand to the handguard. Holsters mirror them. Sprint in / out are short clips that bend the carry arcs. Bipod deploy: a left-hand flick of the legs (`bipod_deploy`), the gun set down (owner → `World`).

### 8.4 Checks (`gun_clips.py --check`, exit 1)
60 fps forward kinematics with the gun and its parts; ≤ 20° per frame on every joint, the gun pose and the parts, except within ±1 frame of a `snap` event; hand residual ≤ 0.1 stud wherever the IK weight is 1; the mag is always somewhere (gun / hand / hidden / dropped); event order (`mag_release` < `mag_drop` < `mag_grab` < `mag_insert`); no gun point inside the torso or head; the muzzle never sweeps across the own head; `commitAt` ≥ `cancelUntil`. `--render` writes filmstrips (15 fps) to look at.

Pickups: a server model tagged `FirearmPickup` with `Firearm`, `GunAmmo`, `GunReserve` (clients dress it with `GunModel`).

### 9.2 The shooter's client (predicted)

1. Fire loop on Heartbeat with an accumulator: shots fall at exact `60 / rpm` intervals whatever the frame rate (several per frame if needed); semi clicks are buffered 0.1 s if early.
2. Local checks mirror the server (drawn, stance allows, not obstructed, ammo / chambered, interval, not busy / stunned / safe zone). The trigger click on empty plays a dry click and, for the pistol, nothing else.
3. Aim point P: a ray from the camera through the screen centre (excluding our body, debris, casings) up to `range`. Origin O = the `Muzzle` attachment's world position. The bullet goes O → P. If the muzzle ray hits something more than 1 stud before P (a corner the camera sees past), THAT is where it hits, and the crosshair shows the blocked mark: no shooting around corners the gun can't see (Mattson's multiplayer warning).
4. Spread: `Ballistics.spread(seed, def, state)` turns O → P into the pellet / bullet directions (seed = shotId hashed with a per-life random sent by the server at draw).
5. Client raycasts against the world and the REST-POSE boxes of the others where we see them (`Shared/Firearms/Ballistics` with `BoxMath`, the `HitPrediction` approach): the predicted zone is what the server will compute.
6. Immediately: flash, light, sound, casing, recoil (camera + body), tracer, world impacts, a small puff on a body hit (blood waits for the server, as melee).
7. Send `FireShot`. Reloads, draws and so on are played at once and sent as `GunAction`; `ShotRefused` resyncs the counters (no visual rollback).

### 9.3 Server validation (`Firearms/Validate.luau`)

In order; any failure = `ShotRefused` (and the shot is not relayed):
1. Types and ranges (numbers finite, unit direction, `shotId` increasing, at most 8 hits, part names in the R6 list).
2. State: the player's character carries `weaponId`, drawn, not stunned / held / knocked down / finishing / in a cinematic / channelling / sliding / climbing / vaulting, not in a safe zone, not sprinting (or the sprint ended ≥ `sprintToFire` × 0.7 ago), not reloading past the cancel window (a shot before it cancels the reload first, as the client does).
3. Rate: a token bucket per player per weapon (capacity 2, refill `rpm / 60 × 1.2`) and accepted shot times ≥ 0.8 × `60 / rpm` apart; the bolt cycle and pump-free semis are capped by the def. Plus the global remote limiter.
4. Ammo: chambered or mag > 0 (server counts); decrement; empty → `boltOpen` per gun.
5. Time: `shotTime` within [now − `REWIND_MAX` − 0.1, now + 0.05]; age = clamp(now − shotTime, 0, `Rewind.amount(player)`).
6. Origin: O within `ORIGIN_SLACK` (pistol 3.5, long guns 4.5 studs, + 1 stud per 10 studs/s of the shooter's speed) of the shooter's server head; and a map raycast from the server head to O must be clear (no muzzle poked through a wall).
7. Direction: within 25° of the shooter's last aim-stream pitch and root yaw; the pellet directions are recomputed from (direction, seed, the server's bloom estimate) and each claimed hit must lie within 0.5° of one.
8. Walls: a map raycast O → each claimed hit; glass panes (`CityGlass`) and breakables in the way break and the shot continues (× 0.85) for rifle-class guns, stop it for the pistol and shotgun.
9. Body: the victim is a registered combatant; its root at the shot time = `Rewind.rootAt(victim, age)`; the pellet ray must cross that rest-pose body's boxes (inflated by `HIT_SLACK`: 0.35 stud horizontally, 0.6 vertically, since vertical motion disagrees most) or the live ones; the zone comes from the box it crosses first (Head / Torso / Arms / Legs). The first body along the ray takes the bullet (sniper: one more at × 0.6).
10. Damage = `damage × zone × falloff(distance) × DAMAGE_SCALE`, then `Combat.firearmHit` (block, parry and dash frames ignored; spawn protection and safe zones respected; KO at 0 HP as for melee; leg hits feed the existing leg damage / limp; bleeding chance per zone).
11. Relay `ShotFired` (unreliable) to everyone else with the validated end points.

Reloads: the client sends `Reload(kind)`; the server checks the state and starts the same timeline (`Timelines.luau`): at `mag_drop` the mag's rounds are gone, at `commitAt` the new count is set, at `bolt_forward` / `charge_release` / `slide_release` the chamber is filled; `ReloadCancel` (or a stun, a sprint, a shot) before `cancelUntil` stops it where it is. `GunAction` carries the server start time so every client plays the clip in sync.

### 9.4 Rates and sizes
LMG: ~13 `FireShot`/s × ~120 bytes, well under the ~500 requests/s budget. Aim: 15 Hz × ~12 bytes. Relays to 15 others: ~25 KB/s in a full LMG burst, acceptable. Server cost per shot ≤ 0.15 ms (a few raycasts, box tests on the rewound bodies).

## 10. Casings, hulls and links (`Casings.luau`)

### 10.1 Simulation
Client-only, every client (the shooter's own at once, the others from `ShotFired` or the clip's `case_eject`). Kinematic, not Roblox physics: Roblox gravity is 5.6× too strong at our scale (RESEARCH §11) and hundreds of physics parts are costly.
- Pool of anchored MeshParts (FBX) or 2-part primitives, CanCollide / CanQuery / CanTouch / CastShadow off, in a client folder `workspace.GunDebris`; moved with `workspace:BulkMoveTo` (`FireCFrameChanged` off).
- Spawn at `CasingSpawn` with the casing axis along its +X. Velocity = the def's speed along the `EjectionPort` +X (randomised ±12°, ±15 %) + the shooter's root velocity; spin 15–40 rev/s about a random axis near the case's short axis (±30 %).
- Integrate gravity 35 studs/s² and drag (cases 0.05 /s, hulls 0.8 /s); a raycast per step (case radius) against the map only.
- Bounce: normal speed × e (brass on concrete 0.45, wood 0.3, metal 0.5, dirt / grass 0.08; steel case −0.05; plastic hull 0.2; links 0.35), tangent × 0.75, spin × 0.6. A tink when the normal speed > 2 studs/s, ≥ 50 ms after the last, at most 3 per casing.
- Roll: under 1.5 studs/s normal speed the case lies on the surface and rolls perpendicular to its axis, decelerating at 25 studs/s²; bottleneck rifle cases roll in an arc (radius ~0.3 stud) around their neck; stop under 0.3 stud/s → at rest (no more updates).
- On a moving / unanchored part: fade after 2 s at rest.

### 10.2 Per weapon (port space: right / forward / up of the gun)

| | Direction (at `EjectionPort` +X) | Speed | Spin | When |
|---|---|---|---|---|
| Pistol 9 mm brass | right, back 20°, up 35° (3:30–4:30 o'clock); 10 % of shots steep up-and-back | 2.5–4 m/s (9–14 studs/s) | 20–40 rev/s | shot frame |
| Shotgun hull | right, forward 10°, up 20° | 1.5–3 m/s (5–11 studs/s) | 6–12 rev/s | shot frame |

| Lmg 5.56 cases / links | cases DOWN, forward 10°; links right, down 10° | 1–2 m/s (3.5–7 studs/s) | 10–20 / 5–10 rev/s | shot frame (both) |

### 10.3 Budget and lifetime
150 casings + 60 links live per client; oldest recycled first (sinks 0.08 stud over 0.5 s, then back to the pool); lifetime 45 s. Shooters beyond 150 studs from the camera: no casings; 80–150 studs: every other one, no sound. At most 60 airborne at once (beyond: the oldest airborne snaps to rest). Impact sounds per surface class (§13); global cap 12 casing sounds per second, nearest first.

## 11. Dropped magazines and pouches (`Magazines.luau`)

- At `mag_drop` (`pouch_drop`, `belt_clear`): hide the gun's `Magazine` part and take a pooled copy (the `<Id>_Mag` mesh + an invisible box collider from the JSON) at the part's exact CFrame.
- Velocity = the finite difference of the animated mag part over the last frame (= the hand's) + the root velocity; angular velocity likewise, plus the weapon's extra (rifle +3–6 rad/s forward rock, pistol a small forward spin).
- Roblox physics (they must tumble and settle on faces): unanchored, collision group `GunDebris` (collides with the map, not characters), CustomPhysicalProperties per material (polymer elasticity 0.25, steel 0.15, cloth 0, friction 0.6), and a world-space VectorForce of `mass × (workspace.Gravity − 35)` upward so it falls at our scale's gravity.
- At rest (< 0.4 stud/s and < 0.5 rad/s for 0.4 s): anchored, force removed. An empty pouch is swapped for the slumped `Lmg_PouchEmpty` mesh on landing (cloth, no bounce).
- Impact sounds per surface: polymer hollow clack, steel heavy clank, cloth thud.
- 20 per client, oldest recycled (sinks), lifetime 90 s. Other players' drops come from their clip events (driven by `GunAction`); a drop more than 0.5 s late is skipped.

## 15. Coexistence with melee and kits

Rule: kits, moves, finishers and the M1 work exactly as today; a gun is an extra layer that only exists while carried.

How players get guns (open question, options):
- **A. World pickups (recommended):** a few spawn points in the city (a pawnshop back room, a police car trunk, a stash in the warehouse), each with a respawn timer; one gun per player; limited ammo (§4.2 start ammo); dropped as a pickup on KO and death, so others can take it. Same mechanics as the thrown bone (`Weapon` attribute, ProximityPrompt). Kits untouched; melee stays the core because guns are scarce, loud and slow to handle.
- **B. A gun kit** (e.g. a "Mercenary" kit whose 4 moves are gun actions): fits the shop and progression, but bends the kit format (continuous fire is not a move) and makes one kit the "gun kit".
- **C. A loadout slot** (a secondary bought in the shop): guns everywhere; melee would die.
- **D. Power weapons (with A):** the sniper and the LMG only from rare timed drops (an announced armoury crate).

Recommendation: **A + D**, with guns OFF in duels (`Combat.resetForRound` already drops the held weapon) and a Studio rack (`TestTools`) for testing.

Rules while armed: the gun's carry speed multiplies the kit's (the Bouncer stays slower); stun → low ready, no fire for the stun; knockdown → the gun drops; dash allowed (carry pose, no fire during it); kit moves auto-holster; firing ends spawn protection like an attack; safe zones: can't draw. A melee hit on someone reloading or aiming flinches the gun (the spring) and cancels a reload before its commit.

## 17. Adapting the player's Unreal reference (71 bones) to R6

The reference is a skeleton with animations; we study and adapt it, we never copy its skeleton. 71 bones is most likely the UE4 mannequin's 68 (RESEARCH §12) plus three extras (a weapon bone, a magazine bone, or virtual bones). The pipeline mirrors `als_dump.py` / `als_retarget.py`:

1. **`tools/anim/ue_ref_dump.py`** (Blender): every bone's head / tail / matrix per frame for each FBX, the hierarchy, the rest pose, the fps → JSON per clip.
2. **`tools/anim/ue_ref_inspect.py`**: prints the hierarchy, names the extras, renders stick-figure contact sheets at 15 fps (the video-reference routine) so every frame is looked at; lists the clips (rifle idle, aim, reloads...).
3. **`tools/anim/ue_gun_retarget.py`**: the mapping below → `GunClip` keys → the normal `gun_clips.py` writer, `--check` and `--render` (our gun, our R6 dummy, side by side with the stick figure).

| UE bones | R6 | How |
|---|---|---|
| `root` | HumanoidRootPart | root motion removed (in place); its yaw → the clip's turn |
| `pelvis` | Root joint position | pelvis translation since rest, scaled so hip height = 2 studs (as `als_retarget`) |
| `spine_01`…`spine_03` | Root joint rotation | `spine_03`'s rotation since rest (the R6 torso is the chest) |
| `neck_01`, `head` | Neck | head rotation relative to `spine_03` |
| `clavicle_l/r` | (absorbed) | R6 shoulder pivots are fixed; the clavicle's lift / reach is folded into the arm aim and the gun placement; logged per frame |
| `upperarm`, `lowerarm`, `hand` (each side) | Left / Right Shoulder | hand ON the gun: solved to our `GripR` / `GripL` on the retargeted gun pose; hand OFF the gun: aim the arm at the wrist position mapped into R6 torso space, projected onto the 1.505-stud reach sphere (keeps the direction, loses the elbow bend) |
| twist bones, 30 finger bones | — | dropped; the index finger's curl gives the trigger-press times; the hand's grip / open state helps place `mag_grab`-type events |
| `thigh`, `calf`, `foot`, `ball` | Hips | as ALS: leg aimed at the ankle, a bent knee slides the leg up (fake knee) |
| `ik_foot_*` | — | foot-plant check only |
| `ik_hand_root`, `ik_hand_gun` | the GUN pose | the key track: the gun's trajectory in torso space, scaled to R6 |
| `ik_hand_l`, `ik_hand_r` | grip markers check, IK weights | relative to `ik_hand_gun` they show where the hands belong; the distance `hand_l` ↔ `ik_hand_l` becomes the `ikLeft` curve (1 when gripping) |
| the 3 extras | to identify | a weapon bone → the gun pose (if `ik_hand_gun` is absent); a magazine bone → the mag track and its events (separation speed spike = `mag_release`, stop = `mag_insert`); a charging-handle / bolt bone → `charge_back` / `bolt_forward` |

**Baking elbow, wrist and clavicle into the gun's placement.** R6 has none of them, and its shoulders are 0.56 m apart with 0.42 m arms against the mannequin's ~0.36 m and ~0.6 m. Copying the gun's trajectory as-is would leave the hands far from it. So each frame is RE-SOLVED with `solve_holds.py`'s solver, the UE gun pose as a prior (a cost to stay near its scaled trajectory and orientation) and the hands as hard constraints: the gun moves where R6's rigid arms can hold it, the torso blade and lean absorb the clavicle, and the gun's own rotation carries what the wrist did. Timing is kept (time-warped only to hit our `commitAt`), arcs and anticipation are kept, the 20°/frame check applies.

Also taken from it: the gun bob and sway in its armed locomotion (amplitudes per phase → our procedural layer's numbers), the stance poses (low / high ready, aim) as priors for the hold solver, and reload beat timings per weapon class (scaled by mass for the others). Its legs are only used if it has armed locomotion that ALS lacks.

## 20. Open questions (decisions for the player)

1. **How do players get guns?** World pickups + rare power drops (recommended), a gun kit, or a loadout slot. Guns in duels: off (recommended).
2. **Lethality vs melee:** a punch does 5, a rifle bullet 38. Keep realistic lethality and balance by scarcity and handling (recommended), or scale gun damage down (`DAMAGE_SCALE`)?
3. **Can a gun finish a KO'd fighter?** Recommended: yes, a point-blank execution as a finisher (head blast gore already exists).
4. **Keys:** `R` reload (pocket item when holstered), `X` draw / holster, `V` mode, `T` bipod, `LeftAlt` shoulder swap?
5. **Tactical reload:** the old mag drops with its rounds lost (recommended, it's what the player asked for: mags on the floor), with an optional long-press retention reload that pockets it (+0.4 s)?
6. **Tracers** on the pistol / shotgun / rifle: none (realistic, recommended) or faint?
7. **Ammo display:** a small discreet counter, or none (count by feel, check the mag with a key)?
8. **Prone:** not in the game; bipods deploy on surfaces only. Add prone later?
9. **Bullets vs dash frames and block:** recommended: neither stops a bullet.
10. **On KO:** every gun drops as a pickup (recommended) or long guns stay slung?
11. **Pistol size on the blocky R6 hand:** real size (0.66 stud long) or × 1.15 (`displayScale`)?
12. **The 3 extra bones** of the UE reference, and which weapons its clips cover.
13. **Triangle budget of the long guns (§5.1 amendments):** keep the rifle (≈ 9.6 k) and the sniper (≈ 16.6 k) over the 8 k target, relying on Roblox's automatic LOD, or re-model them down (the sniper's stock, receiver and scope) to 8 k?
